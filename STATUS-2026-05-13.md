## TL;DR

En 3 días de sprint pasamos de un dashboard que **mostraba mocks en casi todos los tabs** a un dashboard que **lee data real** en Instagram (reels + publicaciones + historias), TikTok (videos por @handle), Discovery (cuestionario estratégico de 40 preguntas persistido en DB), Tareas (kanban con asignación) y Home (métricas globales reales).

El gran tema del sprint fue **Meta / Instagram**: se dejó el OAuth de Meta **implementado en código** pero **no se usa en producción**. El flow real arranca por `@handle` y scrapea vía Apify. Detalle abajo.

## Instagram / Meta — qué pasó exactamente

Esta es la zona que el título de tu mensaje toca: **"quedó conectada la app de Meta pero no del todo"**. Acá la verdad punto por punto.

### Lo que está hecho

1. **OAuth de Meta — wireado en código pero sin UI**
   - Las rutas existen: `app/api/social/[platform]/{connect,callback,disconnect,status}/route.ts` con `platform = instagram`.
   - La app de Meta (App ID + redirect URI) está creada en Meta Developer y el `redirect_uri` registrado literal apunta a la URL de prod de Vercel.
   - Variables de entorno (`META_APP_ID`, `META_APP_SECRET`, etc) están en Vercel dashboard.
   - **El botón de OAuth ya NO se renderiza en `/instagram`.** Lo sacamos en commit `3187158`.

2. **Flow productivo: Apify por `@handle`** (commit `3187158`)
   - El usuario escribe su `@handle` en el banner de Instagram → `POST /api/instagram/connect-handle`.
   - Se crea un `SocialConnection` con `accessToken = ''` y `scopes = 'apify-public'`.
   - El primer `/sync` valida el handle (si no existe, el actor de Apify devuelve vacío y mostramos error en UI).
   - El sync usa el mismo actor que `/competidores` (`apify~instagram-reel-scraper`), pide hasta 50 reels.
   - Devuelve `viewsCount`, `sharesCount`, `durationSec` — campos que el scope básico de Graph API ni siquiera entrega.

3. **`/api/instagram/sync` con dos paths**
   - `accessToken === ''` → Apify (camino real hoy).
   - `accessToken !== ''` → Graph API (camino legacy, intacto). La respuesta incluye `via: 'apify' | 'graph'` para que el cliente distinga.

4. **Stories** (commit `fb33509`) — módulo nuevo, Apify, ventana de 24h, **no se persiste** (las stories caducan, no tiene sentido guardarlas).

5. **Posts no-video** (commit `4295ed9`) — el sync ahora trae imágenes y carruseles, no sólo reels. `UserReel.mediaType` distingue (`VIDEO` / `REELS` / `IMAGE` / `CAROUSEL_ALBUM`).

6. **Paginación cursor-based** (commit `242cf56`) — `/api/instagram/reels?cursor=&limit=` devuelve `{ reels, nextCursor }`. Default 100, max 200.

7. **`/video-feed` ya no es una segunda conexión** (commit `11faca8`) — antes pedía conectar Instagram **otra vez** para alimentar el ranking de top 30d. Ahora deriva del mismo `UserReel`. Se eliminó la duplicación. La URL `/video-feed` redirige a `/instagram?tab=top30d`.

### Lo que NO está hecho (el "no del todo")

- **No hay Meta App Review aprobada.** Sin App Review, los scopes que devuelven métricas serias (`instagram_basic`, `instagram_manage_insights`, `pages_show_list`, `pages_read_engagement`) sólo funcionan para usuarios listados como tester en el panel de Meta Developer. Para abrir a clientes reales habría que pasar App Review, lo cual implica:
  - Política de privacidad publicada en una URL real.
  - Video de uso del producto.
  - Justificar caso de uso para cada scope.
  - Esperar entre 2 y 8 semanas.
- **Decisión explícita:** producto interno con ~10 clientes conocidos → no vale la pena pasar por App Review. Apify cubre la misma surface pública (followers, views, engagement, media). El código de OAuth queda dormante por si más adelante se quiere abrir a usuarios anónimos.
- **Tradeoffs del path Apify:**
  - **No tenemos Insights privados** (impressions, reach, save count, profile visits). Sólo lo que la página pública expone.
  - **Coste por sync** — cada `/sync` quema un run del actor en Apify. Para 10 clientes con sync diario son ~300 runs/mes (≈ entre 5 y 15 USD según el plan).
  - **Riesgo de bloqueo** — si Apify cambia su scraper o Meta endurece, el sync rompe sin aviso. El path OAuth queda como fallback pero requiere reactivar UI.

## Otros bloques cerrados en el sprint

### Discovery (cuestionario estratégico)
- 40 preguntas en 9 bloques (commit `4e3b800`), reemplaza el form genérico anterior.
- Persistencia: las 40 respuestas se guardan **columna por columna** (`q1`...`q40`) en `DiscoveryResponse`, no como JSONB (commit `78a26d0`). Facilita queries y reportes.
- Autosave a `localStorage` (commit `11b6cf4`).
- Visible para cualquier user logueado, **incluso sin ClientAccess** — pensado para que el cliente lo conteste antes de ser onboardeado.
- Viewer `/admin/discovery` (SUPER_ADMIN only) — accordion con los 9 bloques expandibles.

### Tareas
- `Task.assignedTo` (Profile.id, nullable) + filtro "solo mías" + flow de claim (commit `26d2942`).
- La página `/tareas` redirige a `/contenido?tab=tareas` (kanban absorbido como tab).

### Sidebar / Navegación
- Compresión a 8 items: Home · Contenido · Bases · Instagram · YouTube · Competidores · AI · Admin (commit `65b30ef`).
- Rutas absorbidas como tabs: `/tareas` → `/contenido?tab=tareas`, `/video-feed` → `/instagram?tab=top30d`.

### Costos + seguridad
- `summarize-transcript`, `analizador/analyze`, `copy/generate` ahora usan **Claude Haiku** (`CHEAP_MODEL`) en vez de Sonnet (commit `8045848`). El usuario sigue eligiendo modelo en `/competidores` (default Sonnet).
- Tokens sociales **masked** en logs y en el endpoint `/status` — antes se filtraba el token completo en debug.

### UI polish
- Skeletons en Kanban + Home metrics (commit `2a45127`).
- Overlay `?` con atajos de teclado (commit `b3caafb`).
- 3 bugs chicos de Instagram corregidos del audit estático (commit `ff6898c`).
- Home muestra métricas reales **arriba** del dashboard demo (commit `4282e64`).

### Auth
- Volvimos `globalRole` a `PENDING` por defecto en signups (commit `0e5e62e`). El auto-approve a MEMBER fue temporal para testing.

## Variables de entorno que TIENEN que estar en Vercel

(Las que se agregaron / cambiaron este sprint.)

- `APIFY_TOKEN` — usado por Instagram, TikTok, Competidores, video-feed, content-research. Es el cuello de botella crítico: si falla, todo el sync de redes muere.
- `META_APP_ID`, `META_APP_SECRET` — siguen en Vercel, pero **inactivos en el flow productivo**. Mantener hasta confirmar que no se retoma App Review.
- `RESEND_API_KEY` — emails de notify-signup.
- `UPSTASH_REDIS_REST_URL`, `UPSTASH_REDIS_REST_TOKEN` — rate limiting (opcional, degrada a permissive si falta).
